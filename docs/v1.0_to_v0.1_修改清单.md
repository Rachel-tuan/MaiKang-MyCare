### 变更 2 · `metric_definitions` 双来源表达

| 维度 | v1.0 | v0.1 |
|---|---|---|
| 注册模型 | `source_table`（单值）+ `value_column` + `time_column` | **`default_source` + `available_sources` + `source_binding`（JSON）** |
| 双来源指标 | 在 §4.2 拆成「A 类一行 + B 类一行」两处列举 | 合并为**一行一指标**，用 `available_sources` 承载 |
| 消歧 | 靠散文「默认命中 A 类」 | **契约化**：未传 source→`default_source`；传 source 必须 ∈ `available_sources`，否则 `E_INVALID_ARG` |
| 唯一性 | 未显式约束 | **禁止同一 `metric_key` 建两行**（PK 保证 + 应用层断言） |
| 4 个双来源指标 | 分散描述 | 统一冻结：`default_source=daily`、`available_sources=[daily, readings]` |
| `getSeries` 返回 | `resolvedSource` | 新增 **`sourceKey`**（来源枚举），`resolvedSource`（物理表名）保留 |

- **`source_binding` 说明**：因多来源各表列名不同（如 `systolic_pressure`：daily 列 `systolic_pressure`、readings 列 `systolic`），
  单行需容纳多来源解析，故以 JSON 承载。属**同表字段扩展，非新增表**。
- **衍生补充**：`weight` 的 `readings` 来源指向 P1 表 `weight_readings`，Step 1 未建 →
  请求时抛 `E_INVALID_ARG`（`detail.reason='source_not_built'`），不新建表、不静默回落。

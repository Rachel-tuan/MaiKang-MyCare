# 迈康 MyCare · 老年慢病多智能体协同健康管理平台

React 18 · Vite 5 · Ant Design 5 · Express 4 · Node 内置 `node:sqlite`（零 ORM、零原生编译、零第三方数据库依赖）

---

## 项目是什么

迈康 MyCare 面向我国老龄化背景下**老年慢病人群自我管理能力不足、医患信息不对称**的现实痛点，是一款由六个 AI 智能体协同工作的健康管理平台。系统以高血压、糖尿病等老年常见慢病为管理对象，覆盖"感知—分析—决策—预警—执行—陪伴"完整闭环，同时提供患者端与医生端，实现"AI 出稿—医生审核—患者授权"的三段式协同。

### 核心亮点

- **多智能体协同**：健康管家（总控编排）、体征分析、风险预警、方案规划、多模态识别、情感陪伴六个智能体分工明确，通过注册表统一管理，各有独立系统提示词与工具集。
- **医学判定归确定性代码，自然语言表达归大模型**：阈值判定、达标率、风险分级全部由前端与服务端同源规则引擎完成，大模型仅负责将结构化结果转化为老年人听得懂的自然语言。
- **零配置开箱即跑**：数据库使用 Node 内置 `node:sqlite`，无需安装 MySQL/PostgreSQL、无需 ORM、无需 node-gyp 原生编译；不配任何 API Key 也能完整运行（本地推理降级模式）。
- **适老化交互**：大字体、短语句、Web Speech 语音输入、拍照解读化验单/药盒，产品词表严格区分"产品预警等级"与"医学危险分层"。
- **患者隐私设计**：注册不等于授权，医生仅可见患者本人主动授权的数据；密码以 `scrypt` 加盐哈希存储；健康数据不落浏览器 localStorage；前端不接触任何模型密钥。
- **可复现可验收**：配套 22 个验收脚本、800 余项断言，覆盖取数契约、服务端链路与浏览器端到端测试。

### 接入的大模型

| 用途 | 模型 | 说明 |
|---|---|---|
| 文本智能体对话 | `deepseek-flash` | 通过 OpenAI 兼容接口调用，支持 tool calling 与 SSE 流式输出 |
| 视觉图像解读 | `qwen3.8-max` | 识别体检单、化验单、药盒照片；未配置时自动降级为前端 OCR + 文本模型 |

> 本 README 同时承担**参赛作品说明**与**开发者环境配置**两份用途。下方"环境要求/运行方式/环境配置/常见问题"为实用操作指南；系统架构、规则口径、评分设计、系统边界与验收证据，见 `docs/迈康MyCare_最终展示版.html`。

## 一、环境要求

| 项目 | 要求 |
|---|---|
| Node.js | **≥ 22.13**（后端依赖 Node 内置 `node:sqlite`：该模块 v22.5.0 引入、**v22.13.0 起免 `--experimental-sqlite` 标志**。本项目在 **22.22.2** 上验证通过；用 22.5–22.12 需自行加标志，不推荐） |
| npm | ≥ 9（随 Node 一起安装） |
| 操作系统 | Windows / macOS / Linux 均可；`启动项目.bat` 面向 Windows |
| 浏览器 | Chrome / Edge 90+（**语音输入需 Chromium 内核**；Firefox / Safari 不支持 Web Speech） |
| 网络 | 首次需联网装依赖；**调用大模型需能访问模型服务地址**（不配 Key 则无需外网） |

**安装依赖**（首次运行，必须执行一次）：

```bash
npm install
```

> 国内网络若安装缓慢，可先切换镜像源：`npm config set registry https://registry.npmmirror.com`
> 项目**没有任何原生编译依赖**（数据库用 Node 内置 `node:sqlite`），因此不会出现 `node-gyp` / Python 编译失败。

**验证环境是否就绪**：

```bash
node -v          # 应输出 v22.13.0 或更高（如 v22.22.2）
npm -v           # 应输出 9.x 或更高
node -e "require('node:sqlite')"   # 无报错即说明内置数据库可用
```

## 二、运行方式

### 2.1 方式一：双击启动（Windows 推荐）

项目根目录提供两个脚本：

| 脚本 | 作用 |
|---|---|
| **`启动项目.bat`** | 启动前后端，等待服务就绪后打印访问地址与模型状态，并自动打开登录 / 注册页 |
| **`关闭服务.bat`** | 关闭占用 3000 / 3001 的进程（需输入 `y` 确认，避免误杀其他程序） |

双击 `启动项目.bat` 会自动完成：

1. 检查 Node.js 是否安装，并要求 **≥ 22.13**；
2. 检查 `node_modules` 是否存在，缺失则自动 `npm install`；
3. 检查数据库文件是否存在，缺失则给出初始化命令；
4. 检查 3000 / 3001 端口是否被占用 —— **若被占用，会列出占用进程的 PID 与进程名，并按 `y` 直接结束它们后继续启动**（直接回车则安全退出，不做任何改动）。这样「先关再开」只需一步；
5. 分别拉起后端（3001）与前端（3000），轮询探活后打印访问地址、当前模型与前后端就绪状态；
6. 用默认浏览器打开 **登录 / 注册页** `http://127.0.0.1:3000/login` —— 演示固定从这一页开始，不会因为浏览器里残留的登录态直接跳进应用。

> 若不想自动打开浏览器（脚本 / 无头环境），设 `MYCARE_NO_OPEN=1` 即可。
> 启动会弹出两个命令行窗口，**关闭任一窗口即停止对应服务**；要整体停止请用 `关闭服务.bat`。

> **维护约定**：这两个 `.bat` **今后不得写入任何非 ASCII 字符**。
> cmd.exe 在文件含中文时会出现字节偏移漂移，把某一行从字符中间切开并报 `is not recognized as an internal or external command`（与行长、括号、BOM 均无关，只与累积的多字节内容有关）。所有中文文案与判断逻辑都放在 `scripts/launch.mjs` 里由 Node 输出，`.bat` 只保留纯 ASCII 外壳。改用 `npm run dev` 可完全绕过该问题。

### 2.2 方式二：命令行一键启动

```bash
npm run dev     # 同时启动前端 3000 + 智能体服务 3001（依赖需已安装，见 一）
```

浏览器访问 **http://127.0.0.1:3000/login**（登录 / 注册页，与 `启动项目.bat` 的落点一致）。

> 直接访问 `http://127.0.0.1:3000/` 同样可用：未登录会跳到登录页，已登录则直接进入首页。
> 演示建议始终从 `/login` 开始 —— 首页的「一键进入示范病例」入口就在这里。

### 2.3 方式三：分开启动（排查问题时用）

```bash
npm run dev:server   # 终端 1：智能体服务（3001）
npm run dev:web      # 终端 2：前端（3000）
```

### 2.4 生产部署

```bash
npm run build     # 构建前端产物到 dist/
npm start         # 启动服务，自动托管 dist 静态资源
# → http://localhost:3001
```

生产模式仅需暴露 **3001** 一个端口。

### 2.5 登录方式

系统**不使用「任意账号密码即可登录」的演示模式**，身份一律以 `patient_id` 为准：

- **一键进入示范病例**：三位内置示范患者（免密码），登录页直接点击即可；
- **自助注册**：填写基本信息注册新账号，密码以 `scrypt` 加盐哈希存储于服务端，前端不保存任何凭据；
- 注册后可用「忘记密码」通过「用户名 + 注册手机号」双因子重置。

#### 注册用户从 0 到 1 的完整流程

**示范病例只是「档案已经预填好的用户」。** 你自己注册的账号走的是**同一条代码路径** —— 差别只在档案由谁填写、授权由谁点开：

| 步骤 | 操作位置 | 会发生什么 |
|---|---|---|
| ① 注册 | 登录页「注册」页签 | 写入 `patients` 一行。**注册后不自动登录**，会切回登录页并回填用户名 |
| ② 登录 | 登录页 | 校验 `scrypt` 哈希；患者不存在返回 `404 E_PATIENT_NOT_FOUND`，**不会回落到示范患者** |
| ③ 建档 | 首页自动弹出「完善健康档案」 | 六类档案一次提交：基础信息 / 紧急联系人 / 疾病诊断 / 生活画像 / 控制目标 / 用药计划 |
| ④ 今日任务 | 首页自动派生 | 按**你填写的疾病谱**实时派生：高血压 → 血压监测，糖尿病 → 血糖监测，全员 → 运动步数，有药 → 服药 |
| ⑤ 每天记录 | 首页「今日任务」→ 点击进入 | 血压 / 血糖进事实层（**只追加、不覆盖**），日汇总进兼容层 |
| ⑥ 授权医生 | 「我的」→ 我的医疗团队 | **注册不等于授权**：未授权前医生端看不到你；**本人同意后**医生端才可见 |
| ⑦ 医生审核 | 与智能体对话提出调整 | 提案进入医生端待审列表；**医生审结后**，你的今日任务才真正变化 |

- **档案可随时修改**：「我的」页 → 编辑健康档案。修改控制目标**不会改变任何医学判定阈值**。
- **没建档会怎样？** 首页会持续引导你建档（首次进入自动弹出）。未建档时无法派生今日任务、医生端也没有可看的档案。

## 三、环境配置

**本项目的环境配置只有一件事：给智能体服务端填模型密钥。** 其余全部开箱即用 —— 零数据库安装、零 ORM、零原生编译。

### 3.1 配置文件与加载顺序

配置由 **`server/config.js`**（零依赖的极简 dotenv 实现）在**服务端启动时**读取一次，查找顺序如下（**先命中者生效**）：

```
① 系统环境变量（process.env）      ← 优先级最高，适合 CI / 临时覆盖
② 项目根目录 .env.local            ← 推荐：本地真实密钥放这里
③ 项目根目录 .env                  ← 可选：团队共享的非敏感默认值
```

```bash
cp .env.example .env.local      # Windows 可直接复制粘贴并把文件名改为 .env.local
```

| 要点 | 说明 |
|---|---|
| **所有变量均为可选** | 不填任何变量也能完整跑通：无 Key 时自动切换**本地推理引擎（降级模式）**，规则判定、达标率、预警等级全部照常输出 |
| **只有服务端读配置** | **前端不接触任何 Key**，浏览器里也没有任何密钥；所有模型调用都在 3001 完成 |
| 文件格式 | 每行 `KEY=value`；`#` 开头为注释；值可加单/双引号（会自动去掉）；建议存为 **UTF-8** |
| **改完必须让后端重读** | `.env.local` 只在**服务端启动时**读取一次。用 `npm run dev:server` / `npm run dev` / `启动项目.bat` 启动时带 `--watch`，改完**会自动重启**；用 `npm start`（生产模式）启动的需**手动重启** |

### 3.2 变量清单

**A. 模型服务**（写在 `.env.local` 里，由 `server/config.js` 统一加载）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 空 | **唯一需要你填的东西**。留空则运行于本地推理降级模式。获取：https://platform.deepseek.com/api_keys |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | 模型服务地址（走代理/中转时改这里） |
| `DEEPSEEK_MODEL` | `deepseek-flash` | 模型名称。旧名 `deepseek-chat` 已下线，请求会被路由到同一模型 |
| `DEEPSEEK_TEMPERATURE` | `0.6` | 默认温度（各智能体内部有覆盖） |
| `DEEPSEEK_TIMEOUT_MS` | `120000` | 单次模型请求超时（2 分钟） |
| `VISION_API_KEY` | 空 | 可选：视觉模型密钥（OpenAI 兼容接口） |
| `VISION_BASE_URL` | DashScope 兼容端点 | 视觉模型服务地址 |
| `VISION_MODEL` | `qwen3.8-max` | 视觉模型名称 |
| `PORT` | `3001` | **智能体服务**端口。⚠️ 改动后必须同步改 `vite.config.js` 里 `proxy['/api'].target` |
| `ALLOW_MOCK_FALLBACK` | `true` | 是否允许「模型不可用 / 调用失败时降级为本地推理引擎」。默认 `true` 保证演示流程不中断；设为 `false` 进入**排障模式**：无 Key 直接报错、模型调用失败原样抛出真实错误（详见 3.4） |

**B. 运行期环境变量**（⚠️ **必须用系统环境变量，写进 `.env.local` 不生效**）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `MYCARE_DB_PATH` | `data/mycare.db` | 数据库文件路径，用法见 3.5 |

> ⚠️ **务必注意**：`MYCARE_DB_PATH` 由 `server/data/db.js` **直接读取 `process.env`**，**不经过 `.env.local` 的解析**。
> 把它写进 `.env.local` **既不会生效、也不会报错** —— 你以为在用副本库，实际仍在写主库。必须像 3.5 那样在**启动命令前**设置。

### 3.3 四种典型配置

**① 零配置（跑通全流程、看规则与页面，不调模型）**

```bash
# 什么都不用配，直接启动
npm run dev
```

**② 接真实模型（推荐，智能体输出自然语言分析）**

```ini
# .env.local
DEEPSEEK_API_KEY=sk-你的密钥
```

**③ 再加图像解读（可选，识别体检单/血糖仪照片）**

```ini
# .env.local
DEEPSEEK_API_KEY=sk-你的密钥
VISION_API_KEY=sk-你的视觉模型密钥
VISION_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
VISION_MODEL=qwen3.8-max
```

> 不配 `VISION_*` 时，图像解读会自动降级为「前端 OCR + 文本模型」，功能仍可用。
> 注意：视觉走 OCR 是**真实能力**（不是降级模拟），因此不受 `ALLOW_MOCK_FALLBACK` 影响。

**④ 排障模式（确认 Key 到底有没有被读到）**

```ini
# .env.local
DEEPSEEK_API_KEY=sk-你的密钥
ALLOW_MOCK_FALLBACK=false      # 关掉一切「安静降级」
```

开启后：**无 Key 就直接报错**、**模型调用失败就把 401 / 超时 / 配额错误原样抛出**，不再用本地模板兜住。
默认的 `true` 会把这类真实故障掩盖成「看着正常的降级输出」，排障时反而更难发现。日常演示请保持默认 `true`。

### 3.4 确认配置是否生效

**看启动日志**（后端控制台启动时会打印「模型：」「视觉：」两行）：

```
# 已配 Key
  迈康 MyCare 智能体服务已启动
  → http://localhost:3001
  模型：deepseek-flash
  视觉：qwen3.8-max         # 未配置视觉模型时该行显示「未配置，图像走 OCR 通道」

# 未读到 Key（仍在正常运行的降级模式）
  模型：未配置 Key，运行于本地推理引擎（降级模式）
```

**查状态接口**：

```bash
curl http://127.0.0.1:3001/api/status        # 直连后端
curl http://127.0.0.1:3000/api/status        # 经前端代理（开发模式下两者等价）

# 已配好 Key 时的真实返回：
# {"app":"迈康 MyCare","version":"2.0.0","modelConfigured":true,"model":"deepseek-flash",
#  "visionConfigured":true,"capabilities":["multi-agent-orchestration","tool-calling","streaming","voice","vision-input"]}
```

`modelConfigured: true` 即表示配置已被正确读取。若日志显示仍是「降级模式」，按顺序排查：

1. 文件是否叫 `.env.local`（不是 `.env.local.txt` —— Windows 隐藏扩展名最容易踩）；
2. 是否放在了**项目根目录**（与 `package.json` 同级），不是 `server/` 下；
3. 值两端有无多余空格，或误加了中文引号；
4. **改完是否重启了后端**（见 3.1）；
5. 想一步到位就用**排障模式**：在 `.env.local` 里加一行 `ALLOW_MOCK_FALLBACK=false` 并重启 —— 没读到 Key 时接口会**直接报错**（启动日志的「模型：」一行也会变成醒目警告），而不是安静降级。确认完记得改回 `true`。

> **排障模式改了哪些行为**（`ALLOW_MOCK_FALLBACK=false`）：
>
> | 情形 | 默认 `true` | 排障 `false` |
> |---|---|---|
> | 没配 Key | 安静降级为本地推理引擎 | 抛错：`智能体「…」无法调用大模型：未检测到 DEEPSEEK_API_KEY…` |
> | Key 无效 / 超时 / 配额不足 | 同样被 mock 兜住（**真实错误被掩盖**） | **原样抛出真实错误**（如 `模型服务返回 401：Authentication Fails…`） |
> | `/api/agent/briefing`（纯本地算法） | 正常返回 | **同样正常返回**（不依赖模型，不受影响） |
> | 视觉图像解读（未配 `VISION_*` 时走 OCR） | 回退 OCR | **不变**（OCR 是真实能力，不是降级模拟） |
>
> 当前状态可随时查：`GET /api/status` 的 `mockFallbackAllowed` 字段。
> 相关回归验收：`node scripts/db/verify-fallback-flag.mjs`（29 项）。

### 3.5 演示 / 自测不弄脏主库

`MYCARE_DB_PATH` 可把数据库指向任意路径。演示、录数据、跑验收脚本时指向副本库，主库 `data/mycare.db` 全程只读：

```bash
# 1) 从冻结种子源重建一份干净副本库（默认即 data/mycare-demo.db）
node scripts/db/reset-demo.mjs

# 2) 用副本库启动服务 —— 命令随终端而异：
#    Windows cmd
set MYCARE_DB_PATH=data/mycare-demo.db && npm run dev:server
#    Windows PowerShell
$env:MYCARE_DB_PATH="data/mycare-demo.db"; npm run dev:server
#    macOS / Linux
MYCARE_DB_PATH=data/mycare-demo.db npm run dev:server
```

> **安全提示**：`.env.local` 含真实密钥，已在 `.gitignore` 中排除，**请勿提交、也勿随材料外发**；对外提交只给 `.env.example` 模板。

## 四、常见运行问题

### Q1：启动后页面提示「未检测到智能体服务」

前端（3000）与后端（3001）是分离的，请确认两个进程都在运行。用 `启动项目.bat` 或 `npm run dev` 可同时拉起；也可分终端执行 `npm run dev:server` 与 `npm run dev:web`。

### Q2：双击 `启动项目.bat` 没有反应 / 窗口一闪而过

两个原因，按顺序排查：

1. **换行符被改成了 LF**。该文件必须使用 **CRLF**，否则 cmd 无法正常解析。仓库已通过 `.gitattributes` 锁定该规则，但用某些编辑器或解压工具二次处理仍可能破坏它。
2. **脚本里混入了非 ASCII 中文**（见 2.1 的维护约定）。

实在排查不出来时，直接用 `npm run dev` 绕过脚本。

### Q3：提示「端口已被占用」怎么办？

`启动项目.bat` 会列出占用进程的 **PID 与进程名**，然后问你一句：

- **按 `y` 回车** → 结束这些进程并继续启动。**这就是「重启」的正确做法，一步到位**；
- **直接回车** → 不做任何改动，只关掉本窗口（页面若本来就能打开，说明服务已经在运行，直接访问 http://127.0.0.1:3000/ 即可）。

所以重启时**不需要**先跑 `关闭服务.bat` 再跑 `启动项目.bat`，启动时按一次 `y` 就够了。

若列出的进程名不是 `node.exe`，说明端口是被别的软件占用，请不要按 `y`；改用任务管理器按 PID 定位处理，或改端口。

只想停止服务、不想重启：双击 `关闭服务.bat`（同样输入 `y` 确认，**直接回车即取消**）。

命令行等价写法（把 PID 换成实际值）：

```bash
netstat -ano | findstr ":3001 "     # 查占用进程
taskkill /F /PID <PID>              # 结束它
```

前端端口固定为 3000（`vite.config.js` 里的 `strictPort: true`），**不会**自动漂移。

### Q4：没有模型 API Key 能用吗？

可以。此时系统自动运行于**本地推理引擎**模式：趋势拟合、达标率统计、风险判定、方案生成全部照常执行，只有自然语言表达退化为模板化输出。界面顶部会明确标注当前模式。

配好 Key 后如何确认真的读到了？看后端启动日志的「模型：」一行，或访问 `/api/status` 查 `modelConfigured`，详见 3.4。

### Q5：改了后端代码没生效

后端**没有热重载**（`npm start` 生产模式）。改了 `server/` 下的代码必须重启 3001 进程，否则前端会以旧逻辑响应，表现为登录后各页面报 `404` 或数据不更新。

### Q6：语音 / 图像解读不可用

- **语音输入**：Web Speech API 仅在 Chromium 内核浏览器（Chrome / Edge）上支持；Firefox 下会自动降级为文字输入。
- **图像解读提示「OCR 引擎加载失败」**：OCR 引擎（Tesseract.js）按需从 CDN 加载，离线环境下会失败。此时可在面板中输入框**手动填写报告上的关键信息**（如「空腹血糖 7.8、收缩压 152」），点击「开始解读」即可继续。

## 六、隐私与安全说明

- 本项目为**教学 / 演示**用途，**不是医疗器械**，不做诊断，不替代医生判断。
- 演示数据由项目自行构造，**不来自任何真实患者**。
- 所有医学阈值、评分阶梯、任务频次均为**项目内定义的 Demo 规则**，不构成医学建议。
- 真实密钥只放在 `.env.local`（已在 `.gitignore` 排除），**前端与浏览器不接触任何密钥**。

### 6.1 账号凭据

- 账号密码只以 `scrypt$<salt>$<derived>` 形式存放在服务端 `patients.password_hash`，**前端不保存任何凭据**；
- 示范病例该字段为空（免密演示账号），自助注册账号该字段非空 → **登录强制校验密码**，前端无法绕过。

### 6.2 健康数据不落浏览器

- **健康数据不写入 `localStorage`**：本地存储白名单只有 `user` 与 `userSettings` 两项，其余一律走服务端；
- 所有取数以 `patient_id` 为唯一键经服务端数据库读取，**查不到即 404，绝不回落示范患者**。

### 6.3 医生可见性由患者决定

- **注册不等于授权**：新注册账号只写入一行 `doctor_patient_relations.is_active = 0` 的**未授权**关联，医生端看不到该患者；
- 只有**患者本人在「我的医疗团队」显式同意**后，该行才置为 `is_active = 1`；撤回授权即置回 `0`（**不删除**关联行，也不改动患者任何健康数据）；
- 医生端展示的联系方式与紧急联系人一律**脱敏**（如 `139****1234`、`李华（女儿）138****1234`）。
